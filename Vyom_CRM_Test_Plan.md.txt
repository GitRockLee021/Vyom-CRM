Notes on notable behaviours observed while executing:
- Signup **auto-signs-in** and redirects to `/` (dashboard) — not `/login`.
- Every signup creates a **new workspace as Admin**; there is no "subsequent signup → Consultant" path (team members come via invite).
- Login error text is "Invalid email or password" (not "Invalid credentials"); duplicate-signup text is "An account with this email already exists".
- Forgot-password returns a generic message for unknown emails (anti-enumeration); reset links expire after **1 hour** (not 15 min).
- Client add/edit form requires a **service**; the quick-add modal path in `Clients.jsx` is unused (Add Client routes to `/clients/new`).
- **Stale server detected**: the running API (:5000) accepts `POST /api/clients` **without** `service_ids` (201) even though `clients.routes.js` `syncServices()` returns 400 "At least one service must be selected". See Issues.
- PDF download (html2pdf via CDN) worked during this run.

## Issues Found

| Module | Test Case | Issue | Severity | Steps to Reproduce |
|--------|-----------|-------|----------|-------------------|
| Clients | Import CSV | Import posts clients **without `service_ids`**. On the currently-running (stale) API it creates clients with an empty Services column; once the "≥1 service" rule is active (see below) every imported row will 400. | High | `/clients` → Import → upload a CSV with one row → notice "Imported 1 client(s)" but the client's Services cell is "—". |
| Clients (server) | Valid add / API | Running API does not enforce "At least one service must be selected": `POST /api/clients` with `{name, client_type}` returns 201. Source `clients.routes.js` `syncServices()` returns 400. Server appears stale and needs restart. | High | `POST /api/clients` with body `{name, client_type}` (no `service_ids`) → 201 (expected 400). |
| Authentication | Remember me | No "Remember me" checkbox exists in `Login.jsx`; session persists only in localStorage token until logout/expiry. | Medium | Open `/login` → no "Remember me" control present. |
| Dashboard | API status | No "API online — database connected" badge anywhere in the UI (health data exists at `/api/health` but is not surfaced). | Medium | Login → `/` → no API/DB status indicator. |
| Billing | Invoice number | Auto number format is `VY-YYYY-NNNN` (default prefix `VY-`, configurable), not `INV-YYYY-NNNN`. | Medium | Create invoice → number shown is `VY-2026-0001`. |
| Billing | Send Reminder | No "Send Reminder" button/toast. Only WhatsApp "Send via WhatsApp" / "Send Overdue Reminder" exists. | Medium | Open an unpaid invoice → no "Send Reminder" action. |
| Authentication | Invalid credentials text | Error is "Invalid email or password" (and "An account with this email already exists"), not the documented "Invalid credentials"/"Email already registered". | Low | Login with wrong password → see error text. |
| Authentication | Forgot password (unknown email) | Returns generic "If an account exists…" message instead of "Email not found" (intentional anti-enumeration). | Low | `/forgot-password` with a non-existent email. |
| Authentication | Signup redirect / roles | Signup auto-logs-in and redirects to `/` (not `/login`); every signup is a new-workspace Admin (no "subsequent → Consultant"). | Low | Sign up a second account → lands on dashboard as Admin. |
| Dashboard | Quick actions | "+ Add Client"/"+ Create Invoice" route to `/clients/new` and `/invoices/new` (create forms), not the list pages documented. | Low | Dashboard → click "+ Add Client" → URL is `/clients/new`. |
| Clients / Billing | Success toast | No "Client added"/"Invoice created" toast after saving; the form just redirects to the list. | Low | Add a client/invoice → redirected to list with no toast. |
| Billing | Edit status control | Invoice edit has no dedicated status dropdown; status changes only via "Save as Draft" / "Update" / "Record Payment". | Low | Open `/invoices/:id/edit` → no status select. |
